## Frontend maintenance

asset inventory, approved origin and backend binding after exact-source
qualification. Rehash both executables and budget for installation and
recovery using current cycles, freezing requirements and temporary chunk
storage. Compare authenticated preflight module identities, gameplay head,
source health and receipts. The owner authorizes the specific artifact
and same-ID chunked upgrade. Verify certified module hash, actual browser
delivery, CSP, asset representations, permanent Internet Identity origin,
and paid backend continuity. Keep the backend operating during ordinary
frontend-only maintenance. Recovery uses the same-ID upgrade with the
verified compatible executable.

## Backend and epoch changes

Use separate approval and an exact same-canister rehearsal. Preserve the
paid head, authorization registry, receipts, source position, historical
publication bytes and ordered payment inputs. A durable transition record
can change which decoder is allowed to recover. The Rules19 public pair
understands the current committed compact epoch. A pre-compact predecessor
belongs to an earlier boundary. A Wasm file restores executable software.
Recovery of lost heap or stable memory requires its own verified state
recovery mechanism. Create a production snapshot only on explicit owner
request. Never reinstall a paid canister.

Before an authorized production operation, check fresh and settled cycles,
source and lifecycle health, treasury status and required reserves. Record
permission or observation gaps. Controller settings, funding, transfers,
treasury interventions and Full Speed each require their applicable owner
authorization. [Treasury route](PRELAUNCH_SELF_FUNDING.md) · [Owner sign-in](B2Z_PRELAUNCH_TRICKLE.md#owner-sign-in-acceptance)
