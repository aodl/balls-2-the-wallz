## Capability allocation and wire policy

Rules10 (`B2Z_WAR_CRY_RULES_10`) preserves Rules7 admission/economics/state schema6.
It is distinct from Rules8 delegated authorization and Rules9 territorial clearance.
Memo adapter6, capability `btz-war-cry-1`, max memo32bytes, normalized envelope
`BTZPAY03`, spawn-seed projection `gameplay-semantic-1` are pinned in the exact
certified configuration. A partial flag or local preference cannot enable support.
The unchanged historical v3/v4 parsers continue to reject suffixed commands.

New text form: `<existing FIRE or NEW directive>|<strict UTF-8 cry>`; no extra space.
Empty cry emits the unchanged directive without a separator. MOVE, ANGLE and
unrelated operations cannot carry a suffix. Present empty/multiple separators,
invalid UTF-8 and over32-byte raw memos are rejected, not repaired by the backend.
Legacy numeric/binary/bare text commands retain their interpretation. Spender/
delegated transfers remain inadmissible to ordinary gameplay.

No NFC or whitespace normalization is applied. Single-line international text,
combining marks and legitimate emoji joiners are preserved. Reject C0/C1 controls,
U+2028–202E, U+2066–2069, reserved `|`, NUL and lone surrogates. Backend validates
UTF-8/bytes/text; frontend truncates only whole grapheme prefixes. Available bytes
are `max(0,32 - UTF8(directive).length - 1)`. Never truncate/reformat the directive,
change quantity/prices or split text across payments. Cropped suffixes are not
resurrected when a directive shrinks. IME completion precedes reconciliation/copy.
Raw paste is checked before the browser can replace line breaks in a single-line
input; rejected control/separator text is not silently rewritten. Invalid local
text remains editable through status refresh while copying stays disabled.
A literal typed None is text; the empty placeholder None is not.

BTZPAY03:8-byte magic,32-byte canonical funding account,8-byte big-endian amount,
8-byte canonical command,1-byte cry length, bounded exact UTF-8 cry. Input position
remains the authenticated Ledger position in the existing ordered input. Invalid
memos retain an invalid command and no annotation under existing financial rules.
BTZPAY02 and all historical bytes are unchanged.

The full normalized input remains committed by source/DTR history. Under Rules10
only, seed derivation projects each BTZPAY03 to equivalent BTZPAY02 gameplay bytes.
Cosmetic text cannot reroll an automatic site, including another payment in the
same segment. Earlier rules continue hashing their original normalized inputs.

## Cutover and release separation

Frontend panel release can precede backend capability activation. The decoder is
ready for the new exact identity but Rules7 cannot emit unsupported memos. Backend
candidate installation/activation requires a separately approved artifact/hash.
Controller-only prepare/commit/status use the existing paused, drained source/
Ledger/Index/epoch machinery. Boundary metadata version6 pins predecessor Rules7,
unchanged state hash, source watermark/anchor, Index completeness and adapter4→6.
No mid-batch switch, history rescan, replacement constructor or reverse epoch.

Before activation check current paid module/rules/config/source, balances/receipts,
source pending/inflight/errors, journal stage and retired cursor. Stop on any
mismatch or insufficient safety resources; do not fund/resume/change settings
implicitly. The commit atomically binds the new epoch and source adapter. Preserve
all paid state and treasury values. Once new normalized records/events exist, an
old decoder/backend is not a safe rollback: use a state-preserving compatible fix,
not reinstall/reset or a fabricated Rules7 reverse transition.

Qualification must include actual valueless official Ledger/Index transfers,
independent replay, pinned disposable certificate verification, two observers,
source and cursor recovery, native input and approximately60-second bubble output.
Fixtures/compilation alone are not installed/authentication evidence. Audio/P09
and physical/browser limitations remain separately labelled.

New-capability UTF8 decoders preserve U+FEFF in payload text (`ignoreBOM:true`
in JavaScript). It is never treated as a removable transport marker. A BOM in an
ASCII directive is rejected; a valid BOM-containing cry survives raw/normalized
bytes and JS/native replay unchanged. Shared vectors cover both boundaries.
